# Foundation coverage and limitations

This is an extensible working foundation, not a completed production deployment. The final execution report records which checks actually ran. The distinctions below apply even when every synthetic test passes.

| Requirement area | Foundation coverage | Remaining work |
| --- | --- | --- |
| Equipment and component inventory | Normalized hierarchy, multiple fictional tools/chambers, serialized instances, configurable slots, filters, component detail and historical installation queries. | Approved real catalogs, exact equipment configurations and scale/load validation. The hierarchy is not an OEM physical drawing. |
| Effective lifecycle | Installation/removal, replacement records, compatibility, refurbishment and audited editing APIs. | Corporate maintenance execution workflow, approval gates, stockroom logistics and production concurrency controls. |
| Exposure | Tested duration/source attribution, installation/removal clipping, retained histories, counter edge cases and uncertainty; selected synthetic dimensions. | Approved real counter semantics, complete measurement coverage, full operational workflows for every requested wafer/lot/mechanical/thermal dimension. |
| PM | Explicit synthetic policy basis, threshold proximity, fleet planner and recorded maintenance. | Verified OEM limits, approved site policies, work-order scheduling/dispatch and production PM compliance governance. |
| Failures and downtime | Deduplicated cases, alarms without confirmed failure, evidence, hypotheses, adjudication, interval unions and component attribution. | Production failure adjudication and controlled delay vocabulary. No SEMI E10 certification is claimed. |
| Reliability statistics | Foundational exposure rates/intervals, censored survival, revision comparisons, sufficiency-guarded fitting. | Cohort approval, competing-risk/recurrent-event models, confounding adjustment and validated real assumptions. |
| Prediction | Versioned architecture, synthetic model demonstration, eligibility and leakage guards, unavailable state. | No validated production predictor, real remaining useful life, defensible production failure probabilities or automatic intervention. |
| FDC investigation | Synthetic comparison traces and evidence context. | Approved large-scale trace ingestion, validated operating-state alignment, robust change-point/anomaly analysis and physical precursor confirmation. |
| Adapters and provenance | Six legacy typed file categories; Phase 2 synthetic document contracts, parsers/extraction, source versions, exact evidence, identity/review/promotion, durable jobs and sensor/exposure lineage. | Actual approved identity/source mappings and field authority; every real Samsung/Lam transport/schema/authentication contract, production worker hosting and source-specific operational SLA. |
| Security | Server-side role checks, anonymous synthetic viewer only, configured local tokens, enterprise fail-closed guard, audit records. | Corporate SSO, equipment/tenant-scoped permissions, production export policy, secret-manager wiring, security review and penetration test. |
| Storage/deployment | SQLite local path, PostgreSQL Compose path, migrations, seed, dependency locks and GitLab-compatible CI examples. | Approved hosting, TLS, backup/recovery, observability integration, high availability, TimescaleDB/time-series scaling and load tests. |

All demo values remain explicitly synthetic. OEM specifications are unknown or pending verification. No corporate access is required for local use; no live source connectivity or production accuracy is inferred from local readiness.

The current Phase 2 scope and actual acceptance results are in [SAMSUNG_HANDOFF](SAMSUNG_HANDOFF.md) and [PHASE2_VALIDATION](PHASE2_VALIDATION.md). Original model-production, time-series scale, real OEM/channel validity, SSO and operational release limitations remain.
